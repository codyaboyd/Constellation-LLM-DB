▤
Knowledge
Everything added here is extracted, chunked, embedded locally, and indexed for retrieval.

              

                
Upload
Choose a PDF, DOCX, Markdown, or TXT file. Add an optional title, then select Ingest file.
The document appears in Indexed documents after processing.

                
Manual entry
Give the source a title, paste the text into the editor, and select Add knowledge. This is useful for notes, policies, or short reference material.

                
Web crawl
Enter an https:// or http:// starting URL. Max pages limits the crawl size and Depth limits how many link levels are followed, then Crawl & ingest.
Crawls are bounded and same-origin by default; private-network crawling must be enabled by the operator.

              

              

              

                
Indexed documents
Review each source’s title, type, chunk count, and URI. Select View chunks to expand a document and read its indexed text in plain language. Select Delete to remove all indexed chunks for a source; deletion asks for confirmation. Select Ensure vector index to create the search index when it is missing. If it already exists, the action leaves it unchanged.

                
Good ingestion practice: Use descriptive titles, keep related material together, and start with a small crawl to confirm the extracted content before indexing a larger site.

Query / Retrieval playground
Ask a natural-language question and inspect the JSON response returned by the retrieval pipeline.

              
Question→Embedding search→Candidate passages→Optional reranking→Top results

              

                

                  
ControlWhat it changesStarting point

Candidate KNumber of vector-search candidates considered before final selection. Raising it can improve recall but costs more work.20

                    
nprobesLanceDB search breadth. Leave blank for automatic behavior unless you are tuning the index.Auto

                    
RefineIndex refinement factor. Leave blank for the database default.Auto

                    
Min scoreDiscard results below this score. Leave blank to keep the normal ranking cutoff.None

Tuning pattern: Start with the defaults and reranking enabled. Increase Candidate K when relevant material is being missed; use Top K to control how many passages your downstream application receives.

Connected deployments
Let multiple Constellation instances share model work and knowledge copies.

              
    
                
  1. Enter another deployment’s address, such as http://worker-host:4317.
    2. 
                
  2. Set Preference. Lower values are tried sooner when several healthy deployments can do the same work.
    3. 
                
  3. Select Connect. Both deployments must share the same cluster secret and complete a health check.
    4. 
              

              
Each card explains what the deployment does, whether it is reachable, which services it offers, and whether its search models match this deployment. Select Sync to copy knowledge to a storage-capable deployment, or × to disconnect it.

              
In plain language: A search model turns words into a form the system can compare; a ranking model puts the most useful passages first. Matching models keep results consistent. If no suitable worker is available, the coordinator falls back to local work.

Deployment roles
The node badge tells you which behavior is active.

              

                
All-in-oneRuns the dashboard, knowledge storage, and model work in one place.

                
CoordinatorDirects requests, stores knowledge, and sends model work to workers.

                
Model workerDoes search-model work for other deployments; it does not store knowledge.

                
Knowledge copyKeeps replicated knowledge; it does not run model work.

                
Coordinator + workerCoordinates requests and can also do model work locally.

Local models, APIs & operations
The dashboard is backed by authenticated JSON endpoints for automation.

              

                
Local inference
Embeddings use the configured local Transformers.js model. Reranking uses the configured local Jina reranker. Model readiness is visible on Overview, and Load local models warms both when the node advertises those capabilities.

                
Useful API endpoints
POST /api/queryRetrieve passagesPOST /api/embeddingsCreate embeddingsPOST /api/rerankRerank supplied documentsGET /api/modelsInspect model/runtime readinessGET /healthCheck process health

              

              

              

                

                  
API examples
Copy a complete request for POST /api/query. Set the URL and API key for your deployment first; the key can come from CONSTELLATION_API_KEY or the generated key printed at startup.

                  Bearer auth
                

                

                  

                    
cURLShell

                    
export CONSTELLATION_URL="http://127.0.0.1:4317"
export CONSTELLATION_API_KEY="your-api-key"

curl "$CONSTELLATION_URL/api/query" \
  -H "Authorization: Bearer $CONSTELLATION_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{"query":"What is the refund policy?","topK":5,"rerank":true}'

    headers={"Authorization": f"Bearer {os.environ['CONSTELLATION_API_KEY']}"},

response.raise_for_status()
print(response.json())

GoGo 1.20+

                    
package main

import (
  "bytes"
  "fmt"
  "io"
  "net/http"
  "os"
)

func main() {
  baseURL := os.Getenv("CONSTELLATION_URL")
  if baseURL == "" { baseURL = "http://127.0.0.1:4317" }
  body := bytes.NewBufferString(`{"query":"What is the refund policy?","topK":5,"rerank":true}`)
  req, _ := http.NewRequest("POST", baseURL+"/api/query", body)
  req.Header.Set("Authorization", "Bearer "+os.Getenv("CONSTELLATION_API_KEY"))
  req.Header.Set("Content-Type", "application/json")
  res, err := http.DefaultClient.Do(req)
  if err != nil { panic(err) }
  defer res.Body.Close()
  fmt.Println(res.Status)
  io.Copy(os.Stdout, res.Body)
}

                  

                

                
Use the same Authorization header with /api/embeddings and /api/rerank. For a quick check, GET /health is public; authenticated clients can use GET /api/models to inspect readiness.

              

              

              
Dashboard requests use the signed-in session. API clients can authenticate with Authorization: Bearer <api-key> or X-API-Key; cluster-to-cluster requests use X-Constellation-Cluster-Secret. Keep these credentials private and use TLS outside a trusted network.
